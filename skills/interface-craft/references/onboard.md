# Onboard Mode

Use onboard mode for first-run flows, empty states, activation, and feature
discovery.

## Principles

- Show value through the product, not a tour for its own sake.
- Let experienced users skip guidance when safe.
- Put help near the decision it supports.
- Prefer progressive disclosure over long up-front explanation.
- Empty states should explain what will appear, why it matters, and how to
  start.
- Activation should ask for the smallest useful commitment.

## Patterns

- Welcome or setup screen for products with unavoidable configuration.
- Empty state with sample data, import action, or first item creation.
- Inline tips for features discovered during normal work.
- Checklists only when sequence matters.
- Guided tours only when interaction cannot be understood inline.

## Output

- `Onboarding gap`
- `Activation path`
- `Empty or first-run states`
- `Skip/recovery behavior`
- `Verification`
